# 山河图志 · 全国 5A 与 4A 景区地图

浏览内地 31 个省级行政区的 5,167 处景区，根据等级、自然或人文、去过或想去筛选，查看景区介绍和交通入口。全国、省、市三级地图和名录随项目提供。在线实景检索、外部路线与 GitHub 同步需要联网。

## 用自己的 GitHub Pages 打开地图

1. Fork 这个公开仓库到自己的 GitHub 账号。
2. 在 fork 的 **Settings → Pages → Build and deployment** 中选择 **Deploy from a branch**。
3. 选择默认分支的 **/docs** 并保存。部署成功后点 **Visit site**。普通项目站点网址形如 `https://用户名.github.io/仓库名/`。
4. 在 **我的足迹 → 备份与同步** 中管理记录。仅在同一浏览器使用时，直接标记即可。

主仓库有更新时，在 fork 点击 **Sync fork → Update branch**。Pages 使用同一发布分支重新部署。使用稳定景区 ID 引用足迹，升级地图后可以继续使用原有记录。

## 手机和电脑同步

1. 在自己的 GitHub 个人账号创建一个 **Private** 仓库，例如 `scenic-atlas-data`，勾选 **Add a README file** 初始化默认分支。已提供数据仓库的原站所有者可直接使用。
2. 在 [GitHub 的细粒度令牌设置](https://github.com/settings/personal-access-tokens/new)选择自己的账号、有效期和 **Only select repositories**，仅选择上述私有仓库，授予 **Contents → Read and write**。保留默认的 Metadata 读取权限。
3. 在地图打开 **我的足迹 → 备份与同步**，填写仓库名称和令牌。在自己的设备上勾选 **在此设备上记住令牌**，点击 **连接并合并记录**。此后用同一浏览器打开同一地图会自动同步。手机和电脑各设置一次，可以分别签发令牌。共用设备可保持未勾选，仅在当前页面连接。
4. 首次有记录时，地图会在该仓库默认分支写入 `atlas-records.json`。显示「已同步」后可以在另一设备读取记录。断网时继续标记，当前会话联网后重试，也可点「立即同步」。

选择记住后，浏览器在本机的 IndexedDB 中保存加密令牌及不可导出的密钥。能够运行此站点脚本的同源页面仍有可能使用保存的凭据，请仅在自己信任的站点和浏览器上启用。**清除此设备的令牌** 可断开连接并移除本机凭据，足迹仍然保留。令牌到期、在 GitHub 被撤销或浏览器站点数据被清理后，需要重新连接。

应用核对账号及仓库可见性，自动重连时按已确认的仓库 ID 校验目标，每次写入前再次验证。浏览器直接向 api.github.com 提交令牌。JSON 备份与云端提交仅包含足迹、可选定居点和修改版本。私有仓库的提交历史会保留曾经同步的值，包括旧定居点。

## 导入、导出与旧 HTML 迁移

- 在 **我的足迹 → 备份与同步 → 导出 JSON** 下载备份。使用「导入 JSON」合并已有备份。不同景区、同一景区的「去过」与「想去」分别保留，同一字段按较新的修改版本取值，取消标记和清除定居点同样参与同步。使用自动校时的设备可减少时钟差异。
- 如果使用旧版单文件，在原手机、原浏览器、原文件位置以新版同名 HTML 替换，再打开并导出。新版首次在该位置运行时读取旧版本地存储。打开新的 Pages 网址后，导入刚才的 JSON。原文件的实际存储位置取决于浏览器，聊天软件临时预览有时不能保留记录。
- 单文件可由仓库根目录运行 `python3 scripts/build_single.py 输出文件.html` 生成。此命令只使用 Python 标准库。
- 更换或清理浏览器前请先导出或确认已经同步。保留同一个数据仓库便可在自己的新版本中恢复足迹。

## 本地运行

使用静态服务器提供 `docs/`，例如在仓库中运行 `python3 -m http.server 8000 --directory docs`。使用 `node --test tests/*.test.js` 验证合并和同步逻辑。应用无构建依赖。公共文件与私有数据仓库独立，公开发布目录为 `docs/`。

## 资料与署名

5A 名录核对日期为 2026 年 10 月 20 日，4A 数据整理自 2026 年 11 月 7 至 9 日的开放图集。范围、许可和本地照片署名见 [CREDITS.md](CREDITS.md)。每条景区资料保留来源，在线照片在详情中显示原图和署名。可 fork 本项目并在自己的 GitHub Pages 部署；第三方内容沿用对应来源的使用条件。
